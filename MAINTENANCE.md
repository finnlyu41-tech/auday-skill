# Source and installation maintenance

Before a new independent task or an installation change, read `maintenance.json`
for the maintained repository, branch, source path and upstream. Compare the
installed receipt and actual runtime files with the maintained source. Preserve
local changes and active task versions; stage updates separately. Installed
copies are not Git worktrees. Do not pull a parent repository or reset local work.

Cross-project communication and personal skill-management requirements belong
to AI_Rule. Auday functionality and portable workflow requirements belong in
this project. Phone data, credentials, model files, local paths and per-profile
choices remain in private application data. Never commit user recordings,
transcripts, personal preferences, or private development notes.

Validate portable metadata with the AI_Rule package checker, run the source guard
and affected synthetic tests, then verify selected local capabilities separately.
Setup smoke tests, physical phone connectivity, archive import, re-transcription,
speaker quality and new-chat discovery are separate claims. Keep optional model
downloads outside normal tests. Recheck upstream before merging maintenance;
install only the reviewed commit and retain running jobs on their recorded code.
